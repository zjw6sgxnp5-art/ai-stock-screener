# AI 模型策略

**状态**: Draft v0.1  
**日期**: 2026-05-17  
**结论**: 第一版默认使用在线 GPT 模型，不下载部署本地大模型；架构上保留本地模型适配口。

## 1. 推荐决策

第一版采用：

- 数据层: 本地调用长桥 CLI，缓存到 SQLite。
- 分析层: 本地多因子评分、证据整理、风险规则。
- AI 层: 在线 GPT 模型负责复杂文本理解、事件抽取、牛熊论证、综合研判。
- 备用层: 预留 OpenAI-compatible 接口，未来可接 Ollama、LM Studio 或其他本地模型。

这样系统仍然具备“本地自主编排能力”：数据抓取、分析流程、评分逻辑、证据链和任务调度都在本机完成；只是把最难的自然语言推理交给云端模型。

## 2. 为什么第一版不建议本地大模型

你的电脑是 Apple M5、24GB 内存，可以跑一些量化本地模型，但第一版不建议把本地模型作为核心依赖，原因是：

- 投研分析需要长上下文、多步骤推理、事实约束和较强中文表达，在线旗舰模型明显更稳。
- 本地模型会引入下载、存储、性能、上下文长度、模型选择、提示兼容等额外成本。
- 你明确不需要离线使用，在线模型的收益更大。
- 本地模型更适合做备用、隐私敏感摘要、低成本批处理，而不是第一版核心研判引擎。

## 3. 推荐模型分工

| 任务 | 推荐模型档位 | 说明 |
|---|---|---|
| 单股深度全景分析 | GPT-5.2 | 需要长上下文和强推理 |
| 新闻/公告摘要 | GPT-5 mini | 成本更低，适合批量摘要 |
| 事件抽取/标签分类 | GPT-5 mini 或 GPT-5 nano | 输出结构化 JSON |
| 智能选股理由生成 | GPT-5.2 | 需要把评分和证据讲清楚 |
| 高风险最终研判 | GPT-5.2 pro | 用于更重要、更复杂的标的，按需调用 |
| 本地备用模型 | gpt-oss:20b 或 Qwen 系列 | 后续可选，不作为第一版必须项 |

## 4. 成本控制策略

- 分层调用：小任务用 mini，大任务才用旗舰模型。
- 先规则后 AI：价格、动量、估值、异常检测先本地计算，减少模型输入。
- 缓存摘要：同一新闻/公告只摘要一次。
- 证据压缩：只把相关片段送给模型，不把所有原文整包传入。
- 批量模式：低优先级任务未来可接 Batch/Flex 降成本。
- 分析历史复用：同一股票短时间内只做增量更新。

## 5. 隐私与数据边界

- 第一版建议走 OpenAI API，不建议让用户手动复制到 ChatGPT 网页。
- API Key 只保存在本地环境变量或本地配置文件，不写入前端。
- 发给模型的内容只包含必要片段：股票代码、行情摘要、新闻/公告摘录、财务指标和系统生成的证据包。
- 用户本地自定义笔记、持仓、成本价等敏感信息默认不发送，除非用户明确开启。
- OpenAI API/企业类产品默认不使用输入输出训练模型，除非组织主动选择共享数据。

## 6. 模型接口设计

后端统一抽象一个 `LLMProvider`：

```text
provider=openai
base_url=https://api.openai.com/v1
model_deep=gpt-5.2
model_fast=gpt-5-mini
model_cheap=gpt-5-nano
model_premium=gpt-5.2-pro
```

未来切本地模型时只需改配置：

```text
provider=ollama
base_url=http://localhost:11434/v1
model_deep=gpt-oss:20b
model_fast=qwen3:8b
```

## 7. 第一版 AI 功能边界

第一版 AI 做：

- 新闻、公告、财报摘要。
- 事件抽取。
- 消息情绪判断。
- 牛熊观点。
- 风险清单。
- 投资备忘录。
- 对本地评分结果进行解释。

第一版 AI 不做：

- 自动交易。
- 保证收益预测。
- 无证据的买卖建议。
- 完全黑盒选股。
- 替代财务审计或合规判断。
