# 本地股票智能分析软件需求草案

**状态**: Draft v0.4  
**日期**: 2026-05-17  
**目标**: 先把需求完整化，再进入技术设计和开发  

## 0. 已确认决策

- 第一版主要面向**美股**。
- 不要求离线使用，默认在线工作。
- AI 采用“本地主控 + 在线大模型分析”的架构：本地软件负责数据采集、缓存、评分、证据链和任务编排，在线 GPT 模型负责复杂文本理解、事件抽取和综合研判。
- 本地大模型暂不作为第一版核心依赖，只保留可插拔接口。
- 当前已实现版本已经进入“本地投研工作台原型”：单股全景、轻量智能选股、自选股、分析历史、报告导出和深度分析模块已可用；界面已从展示型卡片页升级为高密度工作台，但 AI 全文理解、提醒调度、行业/主题池和更完整数据源仍需继续迭代。

## 0.1 当前版本与目标差距

当前原型已经覆盖：

- 长桥 CLI 登录与基础状态检测。
- 美股单股行情、K 线、新闻。
- 技术指标、动量、波动、本地评分。
- 公司概览、估值、机构评级、财务快照、SEC/公告列表。
- 可解释因子拆解：价格动量、成交活跃、基本面质量、估值合理性、消息催化、风险惩罚。
- 本地规则版研究简报：一句话结论、牛熊观点、催化、观察项、Thesis Breakers。
- 关联股票网络：同行业、基金/ETF 持仓、投资关系、主要股东关联和联动触发条件。
- 管理层与治理：高管、主要股东、内部人交易、治理评分、红旗和待核验问题。
- 历史争议/声誉风险雷达：多关键词搜索、公司别名过滤、类别/严重性/状态标注。
- 财务质量画像：营收/利润/EPS 增速、ROE、净利率、负债/资产、财务红旗。
- 估值画像：PE、行业中位数、目标价空间、同业估值位置、估值风险。
- 事件时间线：新闻、公告、评级、内部人交易、争议事件聚合。
- 智能选股：用户输入股票池后批量轻量扫描，输出 Top N、标签、理由和风险。
- 多股对比：支持 2-5 只股票横向比较评分、动量、估值、评级、成交额和风险。
- 自选股、分析历史归档、Markdown 报告导出。
- 高密度工作台界面：左侧导航、顶部状态/搜索、紧凑 KPI、表格化候选池、评分公式、因子贡献和可展开分析依据。

尚未完全覆盖：

- 真正的 AI 深度研判：新闻/公告/SEC 文件全文摘要、事件抽取、矛盾识别、逐条证据引用。
- 智能选股增强：行业/主题候选池、风险过滤器、评分回测、选股结果保存与复盘。
- 关联股票网络增强：同地区收入暴露、供应商/客户/竞争对手、ETF/指数成分权重。
- 管理层增强：任期、薪酬激励、历史资本配置、审计师变化、董事会独立性。
- 历史争议增强：事件聚类、去重、时间线状态追踪、法律/财务/品牌影响评估。
- 财报深度增强：多期趋势、现金流质量、债务期限结构、管理层指引变化。
- 监控与提醒：定时刷新、自选股异动、重大新闻/公告/评级提醒、每日摘要。
- 页面体验增强：模块过滤、可视化图表、同屏多股票深度对比、逐条证据引用跳转。

## 1. 产品定位

做一个可本地部署的股票分析软件，帮助个人投资者完成两类核心任务：

1. **智能选股**: 从自选市场或指定股票池中，基于行情、基本面、消息面、事件催化、资金面等维度筛出值得进一步研究的股票，并解释入选原因。
2. **单股全景分析**: 用户输入一个股票代码后，系统自动汇总价格、新闻、公告、财报、分析师观点、社区讨论、行业与宏观背景，并生成结构化研判。

产品不直接替用户下单，不承诺收益，不输出“稳赚”“必涨”式结论。核心价值是把分散信息整合成可追溯、可解释、可复核的研究助手。

## 2. 目标用户与场景

**主要用户**: 有一定股票投资经验，但不想每天手动翻新闻、公告、财报和行情数据的个人投资者。

**典型场景**:

- 开盘前快速查看今天有哪些股票值得关注。
- 输入 `AAPL.US`、`TSLA.US`、`700.HK` 等股票，快速获得全景信息和投资辩证分析。
- 对比多只候选股，理解哪只股票的机会、风险、催化更清晰。
- 跟踪已有持仓，发现重大新闻、财报变化、价格异动、风险信号。

## 3. MVP 范围

第一版建议先做成“本地 Web 应用”，浏览器访问本机地址即可使用。

### 3.1 首页 / 仪表盘

- 展示今日市场概览。
- 展示智能选股 Top N。
- 展示自选股异动提醒。
- 展示最近重要事件：财报、公告、评级变化、重大新闻。

### 3.2 智能选股

用户可以选择市场与股票池：

- 美股: 第一优先级，先支持 `US`。
- 港股: 第二优先级，作为后续扩展或可选市场。
- A 股: 暂不作为第一版重点，取决于数据源稳定性。
- 股票池: 自选股、热门大盘股、指定行业、用户导入列表。

选股模型采用**可解释多因子评分**，第一版不做完全黑盒 AI 推荐。

候选因子：

- **价格动量**: 近 5/20/60 日涨跌幅、相对市场强弱、突破新高/新低。
- **波动与风险**: 近 20 日波动率、最大回撤、跳空风险、成交量异常。
- **资金与交易活跃度**: 成交额、换手变化、资金流向，如果数据源支持则纳入。
- **基本面质量**: 营收增速、利润率、现金流、负债、ROE/ROIC，数据源支持后逐步增强。
- **估值**: PE、PS、EV/EBITDA、股息率、历史分位，先以可取得数据为准。
- **消息热度**: 新闻数量、新闻情绪、重大事件密度、公告变化。
- **催化事件**: 财报日期、产品发布、监管事件、并购、回购、分红、分析师评级变化。
- **风险惩罚**: 负面新闻、业绩暴雷、监管调查、流动性不足、极端波动、财务风险。

输出示例：

- 综合评分: `78/100`
- 机会标签: `业绩催化`、`资金活跃`、`消息热度升温`
- 风险标签: `估值偏高`、`波动放大`
- 入选原因: 3-5 条证据，每条尽量附来源与时间。
- 适合动作: `加入观察`、`等待回调`、`适合进一步研究`，避免直接输出“买入”。

### 3.3 单股全景分析

用户输入股票代码后，系统展示：

1. **行情概览**
   - 最新价、涨跌幅、成交量、成交额、盘前/盘后数据，如权限支持。
   - 近 1D/5D/1M/3M/1Y 价格表现。
   - 简单技术面：均线、RSI、MACD、成交量异动、支撑/压力粗略区间。

2. **消息面**
   - 最新新闻摘要。
   - 重大公告/SEC/HKEX 文件摘要。
   - 财报与业绩电话会摘要。
   - 分析师评级和目标价变化，如果数据源支持。
   - 社区讨论热度与情绪，如果数据源支持。

3. **基本面**
   - 收入、利润、现金流、毛利率、净利率。
   - 资产负债情况。
   - 估值指标。
   - 近几个季度趋势。

4. **行业与宏观**
   - 所属行业表现。
   - 同行业可比公司。
   - 相关宏观变量，例如利率、汇率、大宗商品、政策风险。

5. **关联股票**
   - 同行业股票：行业估值、涨跌幅、估值分位、评分对比。
   - 同地区股票：按公司注册地、主要上市地、收入地区暴露进行归类。
   - 同产业链股票：上游供应商、下游客户、竞争对手、替代技术公司。
   - 同主题股票：AI、半导体、云计算、减肥药、能源转型等主题篮子。
   - 股东/基金关联：同被一批机构重仓、同 ETF/基金持有、13F 共同持仓。
   - 指数/ETF 关联：指数成分、ETF 成分、权重和资金流影响。

6. **管理层与治理**
   - CEO/CFO/董事会核心成员。
   - 任期、过往履历、资本配置记录。
   - 内部人交易。
   - 股权激励与股东利益一致性。
   - 重大管理层变动。
   - 治理红旗：频繁换 CFO、审计意见异常、关联交易、股权高度稀释、诉讼密集。

7. **历史争议与声誉风险**
   - 监管调查、诉讼、罚款、会计争议。
   - 产品安全、数据泄露、隐私争议。
   - 反垄断、劳动纠纷、环保/ESG 争议。
   - 做空报告、审计质疑、管理层诚信问题。
   - AI 需要对争议进行聚类、去重、时间线整理，并区分“已解决/仍悬而未决/反复出现”。

8. **综合研判**
   - 一句话摘要。
   - 牛市观点。
   - 熊市观点。
   - 核心催化。
   - 关键风险。
   - 需要继续验证的问题。
   - 置信度和数据质量评分。
   - Thesis breakers：哪些数据或事件会推翻当前判断。
   - 下一步动作：加入观察、等待财报、等待回调、需要深挖公告等。

9. **证据链**
   - 每个结论尽量能回溯到新闻、公告、行情、财务数据或用户自定义资料。
   - AI 生成内容必须标注来源和更新时间。

### 3.4 自选股与提醒

- 添加、删除、分组自选股。
- 每日自动刷新分析摘要。
- 异动提醒：
  - 价格涨跌超阈值。
  - 成交量明显放大。
  - 出现重大负面/正面新闻。
  - 财报、公告、评级变化。

### 3.5 本地部署

第一版建议：

- 后端: Python + FastAPI。
- 前端: React + Vite，或先用 Streamlit 快速成型。
- 本地数据库: SQLite 起步，后续可升级 DuckDB/PostgreSQL。
- 任务调度: APScheduler 或 Celery/RQ。
- AI 分析: 第一版优先接入 OpenAI 在线模型，支持 OpenAI 兼容 API，预留本地大模型接口。
- 启动方式: `docker compose up` 或一键脚本。
- 数据接入: 优先封装本机 `longbridge` CLI，统一转换成系统内部数据模型。

## 4. 数据源规划

### 4.1 长桥 CLI / OpenAPI

长桥可作为第一版核心市场数据源。当前电脑已安装长桥 CLI：`/opt/homebrew/bin/longbridge`。第一版建议优先通过 CLI 获取数据，因为它已经处理了认证、权限、请求格式和 JSON 输出，后端只需要封装命令调用、缓存、错误处理和字段标准化。

CLI 支持 `--format json`，适合作为本地服务的数据适配层。例如：

```bash
longbridge quote TSLA.US AAPL.US --format json
longbridge news TSLA.US --count 10 --format json
longbridge financial-report TSLA.US --kind ALL --format json
```

认证要求：

```bash
longbridge auth login
```

如果用户未登录，CLI 会返回 `Not authenticated. Please run 'longbridge auth login' first.`。产品里需要在数据源设置页展示认证状态，并在未认证时给出明确修复指引。

第一版优先接入：

- 实时行情。
- 历史 K 线。
- 分时行情。
- 股票基础信息。
- 新闻。
- 公告/监管文件。
- 财务报表。
- 估值。
- 机构评级与目标价。
- 股息、公司行动、财报日历。
- 如权限支持，接入资金流、异动、市场温度、社区话题、机构持仓、内部人交易、做空数据。
- 关联股票：`industry-valuation`、`constituent`、`fund-holder`、`shareholder`、`invest-relation`。
- 管理层：`executive`、`insider-trades`。
- 声誉风险：`news search` 按关键词搜索争议、诉讼、调查、罚款、fraud、scandal、lawsuit、SEC investigation、antitrust、data breach 等。

注意事项：

- 行情权限与 App/Web 权限可能不同，需要在开发者中心单独确认。
- 美股默认权限、港股实时权限、盘前盘后/隔夜权限可能受套餐影响。
- 所有数据需要记录来源、抓取时间和权限状态，避免分析结果被旧数据误导。
- 后端不要直接把 CLI stderr 原样暴露给用户，需要转换成中文错误信息。
- 先支持 CLI 模式，后续如果需要更高性能或更细控制，再切换到 Longbridge SDK/OpenAPI 直连。

### 4.2 公开数据源

作为补充数据源：

- SEC EDGAR: 美股 10-K、10-Q、8-K、proxy 等文件。
- 公司 IR 网站: 财报、业绩 PPT、新闻稿。
- 交易所公告: 港交所、纳斯达克、纽交所等。
- RSS/新闻源: 可配置源，避免强依赖单一新闻 API。
- 用户上传资料: PDF、研报、公告、会议纪要。

### 4.3 暂不优先

- 自动交易。
- 高频盘口策略。
- 付费研报全文抓取。
- 未授权社交平台爬虫。
- 完整财务建模和 DCF 自动估值。

## 5. 智能分析方法

### 5.1 评分结构

建议第一版综合分为 100 分：

| 模块 | 权重 | 说明 |
|---|---:|---|
| 价格与动量 | 20 | 趋势、相对强弱、突破、回撤 |
| 成交与资金 | 15 | 成交活跃度、量价配合、资金流 |
| 基本面质量 | 20 | 增长、利润率、现金流、负债 |
| 估值合理性 | 15 | 相对估值、历史分位、同业比较 |
| 消息与催化 | 20 | 新闻情绪、公告、财报、评级变化 |
| 风险控制 | -10 到 0 | 负面事件、极端波动、流动性不足 |

第一版如果基本面或资金数据不完整，可以动态调整权重，并在页面明确展示“本次评分基于哪些数据”。

### 5.2 关联股票分析

关联股票不是简单列同行，而是回答“如果我要理解这家公司，还必须同时盯哪些股票”。

关联来源：

- 行业可比：同 GICS/长桥行业分类下的公司。
- 估值可比：同业务模式、同增长阶段、同毛利率/利润率区间。
- 产业链可比：供应商、客户、替代品、技术路线竞争者。
- 资金关联：同被 ETF/基金/机构持有，13F 共同出现。
- 地区暴露：公司注册地、收入地区、主要政策风险地区。
- 主题关联：由新闻、业务描述和用户自定义主题抽取。

输出：

- 关联类型。
- 关联强度。
- 相关股票的评分、涨跌、估值、新闻热度。
- 为什么相关：例如“同属 AI 加速芯片竞争链”“同受 HBM 供需影响”“同被大型 ETF 持有”。
- 需要联动监控的触发条件。

### 5.3 管理层与治理分析

管理层分析需要覆盖：

- CEO/CFO/董事会核心人物。
- 任期、过往公司、历史业绩。
- 资本配置：回购、并购、分红、增发、债务管理。
- 内部人交易：买入、卖出、行权、10b5-1 计划。
- 股权激励：是否与长期股东回报一致。
- 治理风险：频繁换 CFO、审计师变动、关联交易、诉讼、稀释。

输出：

- 管理层评分：执行力、可信度、股东友好度、稳定性。
- 正面证据。
- 红旗证据。
- 仍需人工验证的问题。

### 5.4 历史争议与声誉风险分析

争议分析不能只搜索“scandal”，需要多关键词、多语言、多年份聚合。

关键词族：

- 英文：scandal、fraud、lawsuit、investigation、SEC probe、fine、penalty、antitrust、data breach、recall、whistleblower、accounting issue、short report。
- 中文：丑闻、欺诈、诉讼、调查、罚款、处罚、反垄断、数据泄露、召回、做空报告、会计问题、举报。

分析方式：

- 搜索公司名 + 关键词。
- 搜索 ticker + 关键词。
- 对新闻、公告、SEC 文件、8-K、10-K risk factors 进行事件抽取。
- 聚类重复事件，形成时间线。
- 判断事件状态：已解决、进行中、反复出现、不确定。
- 评估影响：法律/财务/品牌/管理层可信度/业务连续性。

输出：

- 历史争议时间线。
- 严重性评分。
- 是否已反映在估值和股价中。
- 是否构成 thesis breaker。
- 证据来源链接。

### 5.5 AI 的角色

AI 不直接替代评分模型，而是负责：

- 汇总长文本新闻、公告、财报。
- 抽取事件、时间、主体、影响方向。
- 识别牛熊观点。
- 生成结构化投资备忘录。
- 对模型评分给出自然语言解释。
- 发现矛盾信息，例如“股价上涨但新闻偏负面”“营收增长但现金流恶化”。
- 关联股票原因解释。
- 管理层履历和争议摘要。
- 历史争议聚类和时间线。
- 从公告和财报中提取 thesis breaker。

### 5.6 防幻觉机制

- 每条关键结论必须有来源或标记为“推断”。
- AI 输出区分事实、推断、观点。
- 展示数据更新时间。
- 对缺失数据明确提示，不用模型硬编。
- 重大结论给出置信度。

## 6. 页面结构

### 6.1 主要导航

- `Dashboard`: 今日概览。
- `Screener`: 智能选股。
- `Stock 360`: 单股全景。
- `Watchlist`: 自选股与提醒。
- `Data Sources`: 数据源和权限状态。
- `Settings`: API Key、模型、刷新频率、市场偏好。

### 6.2 单股页面结构

建议改成“投研工作台”布局，而不是简单上下堆卡片。

顶部固定区：

- 股票代码、名称、价格、涨跌、盘前/盘后。
- 综合评分、数据新鲜度、置信度。
- 快捷动作：刷新、加入自选、生成深度报告、导出 Markdown。

当前实现采用左侧固定导航 + 顶部命令条 + 高密度内容区：

- 左侧导航覆盖单股分析、评分解释、智能选股、多股对比、关联股票、管理层治理、丑闻风险和证据包。
- 顶部命令条展示长桥/OpenAI 状态、当前时间、股票输入、全景数据开关和 GPT 研判开关。
- 首屏三栏展示行情快照、综合评分、投研摘要，避免用户先滚动很久才看到核心判断。
- 评分解释区展示最终评分公式、基础分、多因子分、风险惩罚、每个因子的权重/贡献/证据。
- 智能选股和多股对比使用表格优先布局，便于扫读、排序思维和快速点击进入单股深挖。

第一屏三栏：

- 左侧 `Snapshot`: 行情、技术、关键指标、估值摘要。
- 中间 `AI Research Brief`: 一句话结论、牛熊观点、催化、风险、thesis breakers。
- 右侧 `Timeline`: 新闻、公告、财报、评级、内部人交易。

第二屏模块化标签：

- `Overview`: 公司概览、业务分部、地区收入。
- `Financials`: 多期财务、现金流质量、利润率趋势。
- `Valuation`: 估值历史、同行对比、情景估值。
- `Relations`: 关联股票网络，支持按行业/地区/产业链/ETF/股东过滤。
- `Management`: 高管、董事会、内部人交易、治理红旗。
- `Controversies`: 历史争议、诉讼、处罚、做空报告、时间线。
- `Documents`: SEC 文件、公告、财报 PDF、新闻原文。
- `Evidence`: 所有 AI 结论的证据链。

交互体验：

- 点击任何结论能展开证据来源。
- 每个模块显示数据更新时间和来源。
- 重要红旗用明显但不夸张的风险提示。
- 支持“只看风险”“只看催化”“只看最近 30 天”过滤。
- 支持同屏对比 2-5 只股票。
- 支持保存分析快照，方便复盘模型是否有效。

### 6.3 信息层级优先级

用户打开页面 10 秒内应该看到：

- 这家公司现在发生了什么。
- 为什么值得/不值得继续研究。
- 最大风险是什么。
- 下一个催化是什么。
- 哪些关联股票要一起看。
- 结论基于哪些证据，证据有多新。

## 7. 非功能需求

- 本地优先: 用户 API Key 和缓存数据默认保存在本地。
- 可解释: 评分和结论必须展示依据。
- 可复现: 同一批数据下分析结果可复查。
- 可扩展: 数据源、因子、AI 模型应可插拔。
- 性能: 单股分析首次生成目标小于 30 秒，缓存后小于 3 秒。
- 稳定性: 第三方 API 失败时展示降级结果和错误原因。
- 安全: API Key 不写入前端，不上传用户本地数据，除非用户主动配置云模型。

## 8. 风险与合规边界

- 页面需要展示“仅供研究参考，不构成投资建议”。
- 不输出保证性收益语言。
- 不默认提供买卖点和仓位建议；如果后续需要，应明确风险等级和适用假设。
- 新闻和公告要保留原始链接，避免断章取义。
- 如果接入交易功能，需要单独做权限、风控、日志和确认流程，第一版不做。

## 10. 需要你确认的问题

为了进入技术设计和开发，建议先确认这些问题：

1. **市场优先级**: 第一版先做美股 + 港股，还是也必须覆盖 A 股？
2. **股票池规模**: 先分析自选股几十只，还是一开始就要做全市场扫描？
3. **AI 模型**: 可以使用云端 OpenAI 兼容 API 吗，还是必须支持完全本地模型？
4. **界面速度**: 你更想先快速做出可用原型，还是直接做成更完整的前后端架构？
5. **数据费用**: 是否愿意使用付费行情/新闻权限，还是第一版必须尽量免费？
6. **研判风格**: 你更偏短线消息/技术驱动，还是中长期基本面研究？
7. **是否需要中文优先**: 页面、摘要和研判默认中文，代码和字段英文是否可以？

## 11. 建议的默认决策

如果你没有特殊偏好，我建议第一版这样定：

- 市场: 先做美股 + 港股。
- 更新后市场优先级: 第一版以美股为主，港股作为后续扩展。
- 股票池: 先做自选股和用户导入列表，不做全市场扫描。
- 技术路线: FastAPI + React + SQLite + Docker Compose。
- AI: 默认使用在线 GPT 模型，预留本地模型接口但不要求第一版部署。
- 数据: 长桥为主，公开公告/SEC/公司 IR 为辅。
- 智能选股: 可解释多因子评分 + AI 生成入选理由。
- 风格: 默认中文输出，偏“中短期机会 + 风险提示”，不做自动交易。
